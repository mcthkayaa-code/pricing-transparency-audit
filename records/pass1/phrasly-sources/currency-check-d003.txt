D-003 CURRENCY CHECK — phrasly.ai/pricing
Date: 2026-08-10
Rule: before coding a currency variable non_usd, run ONE independent US-locale check
(curl with Accept-Language: en-US, OR most recent web.archive.org capture). If that
check shows a published USD figure, code USD and log local currency as a display_variant.
If neither state shows USD, non_usd stands.

Attempt 1 — curl with US locale header on the live pricing URL:
  $ curl -s -H "Accept-Language: en-US,en;q=0.9" -A "Mozilla/5.0 ... Chrome/124" \
      https://phrasly.ai/pricing
  Result: HTTP 403, Cloudflare "Just a moment..." interstitial (bot-check challenge
  page only; <title>Just a moment...</title>, cf challenge script). No price content
  of any kind returned, USD or otherwise. Inconclusive on its own (blocked, not a
  vendor-served state).

Attempt 2 — most recent web.archive.org capture (Wayback crawls from the US):
  Lookup: http://archive.org/wayback/available?url=phrasly.ai/pricing
    -> most recent snapshot: http://web.archive.org/web/20260712202952/https://phrasly.ai/pricing
  CDX cross-check confirmed multiple 200-status captures in 2026 (20260131, 20260328,
  20260510 x2, 20260709).
  Fetched raw capture: https://web.archive.org/web/20260712202952id_/https://phrasly.ai/pricing
    -> HTTP 200, 34,722 bytes returned.
  Content inspected (grep for TRY/USD/$/plan names/price patterns): the raw archived
  HTML is a pre-hydration JS-app shell — it contains NEITHER "3 Day Access" / "Unlimited"
  plan text NOR any price figures in any currency. Wayback captured the network response
  before client-side rendering executed, so no price of any kind (USD or TRY) is present
  in this archived representation.

Conclusion: neither independent US-locale check surfaced a USD figure (the first was
blocked by bot-detection before showing any price; the second shows no price at all).
Per protocol: non_usd stands for phrasly.ai's money variables. No display_variant
register event is logged, because that entry type applies only when the US-locale
check DOES show USD (i.e., when our local read is the variant) — here neither state
shows USD, so there is no discrepant "true" state to register against.
Money values on this record are coded non_usd with the TRY figures recorded verbatim
in coder_note, per codebook section 5, sourced from the rendered live-page read
(pricing-rendered.txt in this sources folder).
